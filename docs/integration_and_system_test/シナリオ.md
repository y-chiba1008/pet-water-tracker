# 試験シナリオ

期待どおりなら各シナリオ見出し直下の **OK** にチェックを入れる。不合格は GitHub Issue を新規作成する。

操作の起点 URL は [http://localhost:3000](http://localhost:3000) 。文言は実装どおり（句点・「再読み込み」など）。

通信失敗の手順の本体は [試験データ.md](./試験データ.md) の「7. 通信失敗の起こし方」。

## セット A — 認証・セッション

前提: `db reset` + `seed-users`。ブラウザの当該オリジンのログイン状態を消す（シークレット、または一度ログアウト）。

### AUTH-01 未ログインでアプリに入れない

- [x] OK

1. シークレットウィンドウで [http://localhost:3000/](http://localhost:3000/) を開く
2. [http://localhost:3000/bowls](http://localhost:3000/bowls) を直接開く
3. [http://localhost:3000/bowl-records](http://localhost:3000/bowl-records) 、 `/individual-records` も同様

**期待:** いずれもログイン画面（タイトル「猫の飲水量記録」、ボタン「Google でログイン」）。ホームやフッターナビは出ない。

### AUTH-02 許可アカウントでログインできる

- [x] OK

1. `/login` で「Google でログイン」
2. U-OK を選んで同意する

**期待:** ホーム（タイトル「ホーム」）。フッターに ホーム / 水皿交換 / 個別給水 / 水皿管理。ヘッダー右のアカウントメニューに U-OK のメール。

### AUTH-03 ログイン済みだとログイン画面に戻れない

- [x] OK

1. AUTH-02 の状態で [http://localhost:3000/login](http://localhost:3000/login) を開く

**期待:** ホームへリダイレクトされる。

### AUTH-04 未登録アカウントは入れない

- [x] OK

1. ログアウトする（AUTH-06 を先にやってもよい）
2. シークレットウィンドウ、または Google アカウントを U-NG に切り替える
3. 「Google でログイン」→ U-NG を選ぶ

**期待:** ログイン画面に戻り、「このアカウントではログインできません。」ホームに入れない。  
（Supabase は `enable_signup = false` のため、未作成メールはサインアップ扱いで拒否される）

### AUTH-05 ログイン API 失敗

- [x] OK

1. `/login` を開いた状態で DevTools を Offline にする
2. 「Google でログイン」を押す
3. Online に戻す

**期待:** 「ログインに失敗しました。もう一度お試しください。」Google の同意画面に進まない（進んだ場合は保留とし、手順 7 の「ログインボタン押下時」を再確認）。

### AUTH-06 ログアウト

- [x] OK

1. U-OK でログインした状態で、ヘッダー右「アカウントメニュー」→「ログアウト」
2. [http://localhost:3000/](http://localhost:3000/) を再訪する

**期待:** 押下中は「ログアウト中…」になり、その後ログイン画面。再訪してもログイン画面のまま。

### AUTH-07 未知のパス

- [x] OK

1. 未ログインで [http://localhost:3000/no-such-page](http://localhost:3000/no-such-page)
2. U-OK でログインした状態で同じ URL

**期待:** (1) ログイン画面。(2) ホーム（`*` は `/` へ）。

## セット B — 空状態から記録・集計まで

前提: セット A の U-OK ログイン済み。水皿ゼロ（reset 直後ならこのまま。AUTH のあと reset していないこと）。

セット B の途中で `db reset` しない。通信失敗（ERR）はデータの確認が終わってから行う。

### BOWL-01 水皿管理の空状態

- [x] OK

1. フッター「水皿管理」

**期待:** 「水皿がまだありません」「「水皿を追加」から最初の水皿を登録してください。」設置中カウンタは `0 / 0`。

### BOWL-02 水皿交換の空状態

- [x] OK

1. 「水皿交換」

**期待:** 「水皿がまだありません」「先に水皿管理から水皿を登録してください。」「水皿管理へ」で `/bowls` に遷移する。

### BOWL-03 水皿を追加できる

- [x] OK

1. 水皿管理 → 「水皿を追加」
2. 名前 `リビング` → 保存する（ダイアログの主ボタン）

**期待:** 一覧に「リビング」。バッジ「待機中」、「記録なし」。カウンタ `0 / 1`。

### BOWL-04 2 枚目を追加できる

- [x] OK

1. 同様に `寝室` を追加する

**期待:** リビングと寝室が並ぶ。`0 / 2`。水皿交換に行くと水皿を選べる。

### BOWL-05 名前のバリデーション

- [x] OK

1. 「水皿を追加」で名前を空のまま保存する（空白のみも）
2. `あ`×41 を入れて保存する
3. `あ`×40 で保存する（この水皿は直後に削除してよい。BOWL-07/08 の前でも可）

**期待:** (1)「水皿の名前を入力してください。」(2)「40文字以内で入力してください。」(3) 一覧に追加される。

### BOWL-06 名前を編集できる

- [x] OK

1. リビングの編集 → `リビング南` に変更して保存
2. 水皿交換の選択 UI を見る
3. 名前を `リビング` に戻す（以降のシナリオ表記のため）

**期待:** 一覧と水皿交換の選択肢が新しい名前になる。戻したあとは `リビング`。

### REC-01 進行中なし → 給水開始

- [x] OK

1. 水皿交換でリビングを選ぶ
2. バナーが「待機中」「新しい給水を開始します。」
3. 日時は「現在時刻にする」
4. 新しい容量 200ml（プリセット可）
5. 「記録を保存する」

**期待:** 「給水を開始しました。」バナーが「設置中」。開始容量 200ml。終了用の「残った容量」が出て、開始専用だけだった項目構成が変わる。

### REC-02 水皿管理の設置中表示

- [x] OK

1. 水皿管理を開く

**期待:** リビングは「設置中」、「交換から…経過」。カウンタ `1 / 2`。寝室は「待機中」のまま。

### REC-03 交換（終了と次の開始）

- [x] OK

1. 水皿交換・リビング
2. 残った容量 50ml、新しい容量 200ml、日時はいま
3. 見込みが `200ml − 50ml` の **150ml**
4. 「終了記録と同時に、200ml で新しい給水を開始します。」が出ていることを確認して保存

**期待:** 「水皿の交換を記録しました。」設置中のまま（次サイクル開始 200ml）。ホームの今日は、この時点では個別・寝室片付け前なので **150ml**（SUM-B-01 で確認）。

### REC-04 片付け（終了のみ）

- [x] OK

1. 水皿交換・寝室 → 開始 150ml で保存
2. 続けて残った容量 100ml、**新しい容量は空欄**
3. ヘルパー「空欄のまま保存すると、終了のみ記録します（片付け）。」
4. 保存

**期待:** 「給水を終了しました。」寝室は待機中。水皿管理で寝室が「前回の記録: 今日 HH:mm」。リビングは設置中のまま。ホームの今日は 150 + 50 = **200ml**（まだ個別なし）。

### REC-05 水皿ごとに独立

- [x] OK

1. リビングは設置中、寝室は待機中のまま、水皿を切り替えてフォームが変わることを見る

**期待:** リビング＝残った容量＋任意の新しい容量。寝室＝新しい容量のみ。一方の保存が他方の状態を消さない。

### REC-06 事後入力（過去時刻）

- [x] OK

1. 寝室（待機中）で、日時を D の 00:05（今日かつ開始として妥当な過去）にする。前回の終了より後であること
2. 新しい容量 150ml で開始する
3. すぐ片付け、終了日時を開始より後・いま以前、残り 150ml（飲水量 0）でもよい
  以降の集計を簡単にするため、**この事後サイクルは開始直後に残り 150ml で片付け**し、今日の合計を変えない（0ml）。  
   0ml の日はカレンダーに `0ml` と出る点に注意。今日は既に他記録があるので合計は 200ml のまま

代替（今日の合計を増やしたくない場合）: 日時だけ過去にしてバリデーションが通ること・保存できることだけ確認し、直後に同じ量で片付け 0ml。

**期待:** 未来でなければ保存できる。欠損警告は出ない。

### REC-07 個別給水

- [x] OK

1. 個別給水。日時はいま、飲水量 10ml（`+10ml` プリセット可）
2. 保存

**期待:** 「飲水量 10ml を記録しました。」ホームの今日は **210ml**（水皿交換 150 + 片付け 50 + 個別 10）。進行中リビング 200ml は含めない。

### SUM-B-01 ホーム（セット B の当日）

- [x] OK

1. ホーム。カレンダー表示

**期待:**

- 今日の合計 **210ml**
- 前回の記録が、最後に保存した時刻（個別 10ml ならその `HH:mm`）
- カレンダーの今日セルが `210ml`
- 記録のない他日は `—`
- 「今月の1日平均」は `round(当月合計 / 月1日〜今日の日数)`。セット B のみなら当月合計 210、記録日数 1 日（事後の 0ml を今日に足しているだけなら記録日は今日のみ）



### SUM-B-02 カレンダーとグラフの切り替え

- [x] OK

2. カレンダーに戻す

**期待:** 「直近30日間の飲水量推移」「30日間」。今日付近に 210ml。カードの今日の合計は切り替えで変わらない。

### VAL-01 未来日時

### VAL-04 水皿容量の上下限

### VAL-05 個別給水の上下限

**期待:** 0 は「1ml以上で入力してください。」501 は「500ml以下」。500 は保存可（保存した場合、今日の合計が 210+500 になる。**確認後はセット C に進む前に reset するので残ってよい。SUM-B を VAL より前に実施すること**）。

### BOWL-07 削除のキャンセル

### BOWL-08 削除すると一覧から消える（ログはホームに残る）

## 実施順序（推奨）

1. セット A（AUTH-04 はアカウント切替が必要なので、AUTH-02 の前後どちらかでまとめてよい）
2. セット B: BOWL 空状態 → 追加 → REC → SUM-B → VAL → BOWL 削除 → ERR
3. reset してセット C
