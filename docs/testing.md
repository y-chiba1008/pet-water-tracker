# 単体テスト・カバレッジ方針

Issue [#38](https://github.com/y-chiba1008/pet-water-tracker/issues/38) で決めた方針。新しいロジックを追加・変更するときの判断基準とする。

---

## 目的

- 飲水量計算・異常値判定・集計・バリデーションなど、**業務ロジックの正しさ**を単体テストで担保する
- 異常系・境界条件など、**手動では再現・確認しにくい分岐**の品質を落とさない
- アプリ全体のカバレッジ数値を追いすぎず、テストしやすい層にコストを集中する

---

## テスト対象（絞る）


| 書く                       | 書かない（当面）                     |
| ------------------------ | ---------------------------- |
| `domain/` の純粋関数          | React コンポーネント（見た目・レイアウト）     |
| Zod スキーマ（バリデーション分岐）      | shadcn/ui などの UI ラッパー        |
| 日付・表示ラベル・エラーパース等の `lib/` | Repository（Supabase 直叩き）     |
| 集計・異常判定などバグると困る業務ロジック    | TanStack Query を薄く包むだけの hook |


### 例外

層に関係なく、次はテストを足してよい。

- バグった履歴があるロジック
- 分岐が多く、型やレビューだけでは漏れやすい判定
- **Page レイヤーの通信失敗時 UI**（後述。Testing Library でピンポイント）

### この方針でカバーしないもの

次は単体テスト＋カバレッジ（lines 100%）の対象外。品質は手動確認や必要に応じた別手段で見る。

- Repository 自体の実装（Supabase クライアント呼び出しの詳細）
- 見た目・レイアウト目的のコンポーネントテスト全般
- Supabase / ブラウザに依存した実通信の再現

※ Page の「失敗時に定型文を出す」こと自体は、下のコンポーネントテストで担保してよい。

---

## Page レイヤーの例外処理テスト

通信エラーの **ユーザー向けハンドリングは Page** にある（Repository は `throw`、hook は伝播のみ）。  
この例外表示は、**Testing Library によるコンポーネントテスト**で確認する。

### 方針

- `@testing-library/react` + Vitest（`jsdom`）を用いる
- Repository や実通信は叩かない。**hook（Query / Mutation）をモック**して失敗を注入する
- アサーションは **失敗時メッセージ・再読み込みボタンなど、ユーザーに見える結果**に絞る
- 見た目やレイアウト全体のスナップショットは書かない
- 必要な Page だけピンポイントで書く（全 Page の網羅は必須としない）

### 失敗の注入例

| 操作 | モックの仕方 | 確認すること |
|---|---|---|
| 保存・削除（Mutation） | `mutateAsync` が reject するよう hook をモック | 「保存に失敗しました。もう一度お試しください。」等の定型文 |
| 取得（Query） | hook が `isError: true` を返す／`queryFn` 相当が失敗する状態 | 取得失敗メッセージと「再読み込み」 |

### カバレッジとの関係

Page / コンポーネントは **計測対象外のまま**（lines 100% の範囲に含めない）。  
例外 UI のテストは「手動確認しにくい分岐の品質担保」のための追加手段であり、カバレッジ数値の達成手段ではない。

## カバレッジ



### 計測ツール

Vitest 公式の `@vitest/coverage-v8` を用いる。

### 計測対象

**テスト対象と同じ範囲に絞る。**

- **含める**: `src/features/**/domain/**`、テスト対象としている `**/lib/**`（スキーマ・日付・エラーパース等）
- **除外する**: `components/`、`hooks/`、`api/`、`shared/types/`、エントリポイント、UI 生成物など



### 目標

計測対象の範囲内で **lines 100%** を目指す（満たす）。

- アプリ全体のカバレッジ 100% は目指さない
- `branches` / `functions` の 100% は必須としない（必要なら後から足す）
- 「行が実行された」だけでなく、異常値・境界・空データなど **意図したケースにアサーションを置く**

---



## コマンド（目安）


| コマンド                 | 内容                    |
| -------------------- | --------------------- |
| `pnpm test`          | Vitest ウォッチモード        |
| `pnpm test:run`      | Vitest を1回実行（CI でも使用） |
| `pnpm test:coverage` | カバレッジ計測               |


CI（`.github/workflows/ci.yml`）は現状 `pnpm test:run` でテスト通過をゲートする。カバレッジ閾値（計測対象の lines 100%）の CI ゲートは、計測導入時に合わせて検討・追加する。
